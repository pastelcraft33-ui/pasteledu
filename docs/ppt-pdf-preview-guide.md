# PPT 원본 유지 및 PDF 미리보기 설정

## 동작 방식

- 원본 PPT와 기존 다운로드 버튼은 변경하지 않습니다.
- 사이트 미리보기는 PDF를 한 장씩 표시합니다. PDF의 링크 영역을 클릭하면 새 창으로 연결됩니다. 오른쪽에 별도 링크 목록은 표시하지 않습니다.
- 같은 PDF 안의 페이지 이동 링크도 지원합니다. PDF로 바뀌므로 애니메이션, 동영상 재생, 슬라이드 전환 효과는 사라집니다. 변환 서버에 없는 글꼴은 다른 글꼴로 보일 수 있습니다.
- Vercel 안에 **사이트 프로젝트와 별도의 변환기 프로젝트**를 구성합니다. 추가 서버 업체나 이 Mac의 상시 실행은 필요하지 않습니다. Vercel의 컨테이너 런타임은 베타이므로 계정에서 사용 가능한지 먼저 확인하세요.
- PPT 등록·교체 후 관리자의 로그인 권한으로 변환하고, 결과를 Supabase `ppt-previews`에 저장합니다. 방문 시에는 저장된 PDF만 읽습니다. 변환 실패 시 원본은 유지되며 관리자에서 재시도할 수 있습니다.
- 관리자 화면 밖에서 DB에 직접 등록한 자료는 자동 변환되지 않습니다. 관리자 PDF 미리보기 메뉴에서 실행해야 합니다.

## 1. Supabase SQL 실행

Supabase → SQL Editor → New query에서 `supabase/add-ppt-pdf-previews.sql` 전체를 붙여 넣고 Run을 누르세요. 새 설치에서 최신 `schema.sql`을 실행한 경우 중복 실행할 필요는 없습니다.

이 SQL은 `ppt_materials.preview_pdf_url`, `preview_source_url`을 추가하고 PDF 전용 버킷을 생성합니다. 원본 PPT 및 기존 자료를 지우지 않습니다. PDF 공개 읽기와 허용된 관리자 이메일의 업로드·삭제 정책을 설정합니다. 프로젝트의 기존 테이블 RLS 정책은 변경하지 않습니다.

## 2. Vercel 변환기 프로젝트 준비

아직 Git에 올리거나 배포하지 말라는 요청 중이라면 이 단계는 실행하지 말고 코드 검증까지만 진행하세요.

1. Vercel에서 기존 사이트 프로젝트를 변경하지 말고 **Add New → Project**로 새 변환기 프로젝트를 만듭니다.
2. 같은 저장소를 선택하고 **Root Directory**를 `services/ppt-converter`로 지정합니다.
3. Framework Preset은 **Container**를 선택합니다. 이 폴더의 Dockerfile을 사용합니다. Next.js 사이트 프로젝트의 프레임워크나 루트 폴더는 바꾸지 마세요.
4. 다음 환경변수를 넣습니다.

| 이름 | 값 |
| --- | --- |
| NEXT_PUBLIC_SUPABASE_URL | 기존 사이트와 같은 Supabase URL |
| NEXT_PUBLIC_SUPABASE_ANON_KEY | 기존 사이트와 같은 publishable 키 |
| PPT_CONVERTER_TOKEN | 새로 만든 32자 이상의 무작위 비밀값 |
| PORT | 3000 |

비밀값은 비밀번호 관리 도구로 만들거나 터미널에서 `openssl rand -hex 32`로 생성할 수 있습니다. 이 값은 Git이나 채팅에 올리지 말고 Vercel 환경변수에만 저장합니다. `NEXT_PUBLIC_`을 붙이지 않습니다. Supabase secret 또는 service_role 키를 사용하지 않습니다.

5. Vercel 함수 최대 실행 시간은 300초로 준비합니다. 컨테이너 지원 및 실행 제한은 계정 설정에서 확인하세요.
6. 배포 후 `https://변환기주소/health`가 `{"status":"ok"}`를 반환하는지 확인합니다. 변환 API는 별도 비밀값과 실제 Supabase 관리자 로그인 토큰을 모두 검증합니다.
7. 사이트 프로젝트에는 다음 서버 환경변수를 추가하고, 실제 사이트 배포 전 로컬에서도 같은 값으로 검증합니다.

| 이름 | 값 |
| --- | --- |
| PPT_CONVERTER_URL | 새 변환기 프로젝트의 Production HTTPS 주소 |
| PPT_CONVERTER_TOKEN | 변환기와 정확히 같은 무작위 비밀값 |

추가 비용을 결제하거나 요금제를 변경해야 하는 경우 직접 확인한 뒤 결정하세요. 변환 CPU·메모리 사용량과 PDF 저장·전송량이 발생하며 무료 사용을 보장하지 않습니다.

## 3. 기존 자료 일괄 변환

1. 관리자 로그인 후 **PDF 미리보기** 메뉴를 엽니다.
2. **미생성 자료 일괄 변환**을 누릅니다. 화면을 닫지 않고 완료까지 기다립니다.
3. 순서대로 한 자료씩 처리하며, 이미 원본과 일치하는 PDF가 있으면 건너뜁니다. 중단하거나 실패한 자료는 같은 버튼으로 다시 처리할 수 있습니다.
4. 개별 자료의 **다시 생성**으로 변환 결과를 재생성할 수 있습니다.
5. 실제 PPT 여러 개에서 글꼴·이미지·링크 위치·페이지 수를 확인하세요. 특히 유튜브, 상품 링크, 내부 페이지 이동을 확인합니다. 암호화·손상 파일은 변환되지 않을 수 있습니다.
6. 일괄 변환이 끝나기 전에 사이트를 PDF 전용 버전으로 배포하면, 미변환 자료는 준비 중 화면으로 표시됩니다. **일괄 변환과 검증을 마친 뒤 사이트를 배포하세요.**

## 4. 이후 신규 등록 및 교체

단일 자료 저장, 기존 자료 수정, 대량 업로드가 완료되면 PDF 변환을 요청합니다. 기존 PDF와 원본 주소가 같으면 중복 변환하지 않습니다. 새 PPT를 선택하면 새 원본 주소를 사용하므로 재변환됩니다. 실패하더라도 원본 등록은 성공으로 유지하고 PDF 재시도 안내를 표시합니다.

변환 중 원본이 바뀌면 이전 PDF를 새 원본에 연결하지 않습니다. 원본과 일치하지 않는 PDF도 미리보기에 표시하지 않습니다. PDF 재생성 시 새 저장 주소를 사용해 오래된 브라우저 캐시를 피합니다. 이전 PDF는 즉시 지우지 않아 공유·접속 중인 파일을 보호하므로, 장기 운영 시 더 이상 참조하지 않는 PDF의 정리가 필요할 수 있습니다.

## 로컬 개발 검증

Docker Desktop 실행 후 프로젝트 루트에서:

```sh
docker build -t pastel-pdf-converter:local services/ppt-converter
```

변환기의 환경변수를 설정한 뒤 로컬 전용으로 실행합니다. 비밀값을 명령에 직접 적거나 Git에 기록하지 마세요.

```sh
docker run --rm -p 127.0.0.1:3002:3000 \
  -e NEXT_PUBLIC_SUPABASE_URL -e NEXT_PUBLIC_SUPABASE_ANON_KEY \
  -e PPT_CONVERTER_TOKEN pastel-pdf-converter:local
```

사이트 `.env.local`에는 `PPT_CONVERTER_URL=http://127.0.0.1:3002`와 같은 비밀값을 넣고 개발 서버를 다시 실행합니다. HTTP 변환기 주소는 개발 환경의 127.0.0.1만 허용하고, 운영은 HTTPS만 허용합니다. 로컬 환경변수 파일은 Git에 올리지 않습니다.

인증 및 원본 URL 검증 테스트:

```sh
node --test services/ppt-converter/server.test.mjs
npm run lint
npm run build
```

현재 제한은 원본·결과 각각 100MB, 변환 프로세스 180초, 전체 변환 요청 약 235초입니다. 동시에 같은 컨테이너에 요청하면 추가 요청은 재시도 안내를 반환합니다. 파일 내용은 컨테이너 임시 폴더에서만 처리 후 삭제하며, 영구 저장은 Supabase에만 합니다.
